## Summary

For Klipper printer profiles, PrusaSlicer sanitizes object names and replaces `.` with `_` (`src/libslic3r/src/libslic3r/GCode/LabelObjects.cpp:117-120`, banned set includes `.`). An STL named `temptower_v1_PLA_230to190_step5_h10_b1.4_m104.stl` becomes the label `temptower_v1_PLA_230to190_step5_h10_b1_4_m104_stl`. The decoder's `NUMBER` pattern (`packages/core/src/filename-codec.ts:25-28`) accepts only `.` as decimal separator, so `decodeTowerConfigName` returns null and `recoverTowerConfig` (`packages/core/src/recover-config.ts:22-25`) finds no config from the object label.

Every material preset defaults to `baseHeight: 1.4` (`packages/core/src/tower-config.ts`), so a default tower sliced for Klipper and then renamed hits this. ADR-0005 documents recovery from the object label for a renamed G-code.

## Reproduction

`inspectGcode(loadGcodeText('renamed.gcode', text))` with:

```
; generated by PrusaSlicer 2.9.0
EXCLUDE_OBJECT_DEFINE NAME='temptower_v1_PLA_230to190_step5_h10_b1_4_m104_stl' CENTER=1,2
G1 X1 E1
```

Observed: `recovered` is `null`.

Same input with label `temptower_v1_PLA_230to190_step5_h10_b2_m104_stl` (integer base): `recovered` is `{"config":{...,"baseHeight":2,...},"source":"object-label"}`.

## Impact

Low: the UI falls back to manual entry (never a wrong config), the file-name path still works when the G-code keeps the STL base name, and `height-mismatch` catches a wrong manual entry.

## Suggested fix

Decode-only change: in `decodeTowerConfigName`, also accept `_` as the decimal separator for the `h` and `b` values (and the `.stl`/`_stl` suffix needs no handling, since the pattern matches anywhere). The encoded v1 name stays unchanged, so no new filename version or ADR is needed. Add a recovery test with a sanitized Klipper label.
