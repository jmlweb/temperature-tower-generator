## Summary

A single-object, uniform-layer PrusaSlicer slice whose `first_layer_height` is above the Z of the start G-code's intro/purge line is blocked with a `variable-layer-height` error and also gets a spurious `marker-mismatch` warning. The file is valid; the download is refused.

## Where

- `packages/core/src/motion.ts:66` (`layers.push`): the purge line extrudes with XY movement, so it becomes layer 0 at the purge Z. When the first object layer is at a higher Z, it becomes a separate layer 1 whose `height` is `first_layer_height - purgeZ`.
- `packages/core/src/validation.ts:57`: `layers.slice(1)` exempts only layer 0 from the uniform-height check, on the premise that layer 0 is the first object layer. Here layer 1 is the real first layer, so its short height counts as "varies".
- `packages/core/src/validation.ts:97-104` (marker check): the purge layer has no `;LAYER_CHANGE` marker, so the counts differ by one and `marker-mismatch` fires.
- The stock MK3S start G-code hardcodes the purge Z: `fixtures/prusaslicer/zhop-off_abs-e_0.20.gcode:37` is `G1 Z0.2 F720`, and the `start_gcode` template at `:32840` contains the literal `G1 Z0.2 F720`, not `[first_layer_height]`. The Core One render in `fixtures/prusaslicer/coreone-gui.golden.gcode:329` purges at `Z0.2` too (whether its template is literal cannot be told from a 0.2 mm first-layer slice).
- `docs/adr/0009-base-prints-at-tier-0-temperature.md:6` assumes the purge "extrudes at the first layer's Z"; that only holds when `first_layer_height` is 0.2.

All fixtures use `first_layer_height = 0.2`, so no test covers this.

## Reproduction

Node 24 (type stripping), from the repo root:

```ts
import { processGcode, loadGcodeText } from './packages/core/src/index.ts'
const config = { material: 'PLA', startTemperature: 230, endTemperature: 220, step: 5, blockHeight: 6, baseHeight: 1.5, waitForTemperature: false } as const
const lines = ['; generated by PrusaSlicer 2.9.0', 'G90', 'M82', 'M104 S215', 'M109 S215', 'G28',
  'G1 Z0.2 F720', 'G1 Y-3 F1000', 'G92 E0', 'G1 X60 E9 F1000', 'G1 X100 E12.5 F1000', 'G92 E0']
let e = 0
const zs = [0.3]; while (zs.at(-1)! < 19.5 - 1e-6) zs.push(Math.round((zs.at(-1)! + 0.2) * 1000) / 1000)
for (const z of zs) lines.push(';LAYER_CHANGE', `;Z:${z}`, `G1 Z${z}`, 'G1 X10 Y10', `G1 X20 Y10 E${(e += 1).toFixed(3)}`, `G1 X20 Y20 E${(e += 1).toFixed(3)}`)
lines.push('M104 S0')
const r = processGcode({ file: loadGcodeText('t.gcode', lines.join('\n') + '\n'), config })
console.log(r.report.errors, r.report.warnings.map((w) => w.code))
```

(First layer 0.3 mm, then 0.2 mm layers to 19.5 mm = `b + n·h`.)

Observed:

```
error variable-layer-height: "Layer height varies (1 layers differ from 0.2 mm). Variable layer height is not supported."
warnings: [ 'marker-mismatch' ]
layers: count 98 (97 markers), typicalHeight 0.2, maxZ 19.5, expectedHeight 19.5
```

Expected: no error and no marker warning; the file is a uniform 0.2 mm slice with a 0.3 mm first layer.

A first layer at or below the purge Z (for example 0.15 or 0.2 mm) is not affected: a lower first layer is marked `descending` at index 1 and skipped. Only a first layer above the purge Z fails.

## Impact

Users who raise the first layer height for adhesion (0.25 or 0.3 mm is common, and some nozzle profiles default to it) get a blocking error that tells them to turn off a variable layer height they never turned on.
